# 61 · 更新与版本

## 前言

- **适用对象**：需要升级到新版本、或检查当前版本的用户
- **本篇解决的问题**：在哪里检查更新；各个状态文案表示什么；下载与安装过程会做什么、会不会动数据
- **前提条件**：检查与下载需要能访问 GitHub；安装由你确认后手动完成

---

## 具体方法

### 1. 在哪里看版本

- 路径：标题栏信息按钮 → `关于软件` → 点 `版本更新` 打开版本弹窗。
- 弹窗顶部显示当前版本号（例如 `v0.1.0`）与「预览版」标记。
- 弹窗打开时自动检查一次，之后也可手动点 `检查更新`。

### 2. 状态文案对照

| 状态 | 界面文案 | 含义 |
| --- | --- | --- |
| 等待 | `等待检查` | 尚未开始 |
| 检查中 | `正在检查…` | 请求 GitHub 上的最新版本号 |
| 有新版本 | `发现新版本 v…，正在下载…` | 已开始下载安装包 |
| 下载中 | `正在下载 N%` | 显示百分比进度 |
| 已下载 | `新版本已下载，打开安装包安装` | 同时出现 `打开安装包` 与 `去发布页下载` |
| 已打开 | `已打开安装包，按提示完成安装` | 安装向导已启动，按系统提示继续 |
| 无更新 | `已经是最新版本` | 当前已是最新 |
| 失败 | `更新失败：…` | 后面跟具体原因 |

检查中、下载中时 `检查更新` 按钮不可点，避免重复触发。

### 3. 下载与安装

1. 有新版本时，程序自动从 GitHub Releases 下载最新发布中的安装包，无需另点按钮。
2. 下载完成后出现 `打开安装包` 与 `去发布页下载`。
3. 点 `打开安装包`，系统会像双击安装包一样打开安装向导；程序不会在后台替你运行安装包，也不会自动退出。
4. 按 Windows 提示完成安装（可能询问是否允许运行），装完手动打开班集即可。

数据与账号不受影响：安装包只替换程序文件，数据目录原样保留，升级后无需重新登录或重新配置。

> **说明**：安装包目前没有发布者签名，Windows 可能提示「未知发布者」。弹窗里也会提示确认来源；请只从本项目发布页获取安装包。

> **易错**：点 `打开安装包` 前先保存正在编辑的内容；安装器会关闭占用文件的进程，未保存的界面编辑会丢失。

### 4. 失败时常见原因

| 文案 | 常见原因 |
| --- | --- |
| `网络连接失败…` | 无法访问 GitHub（代理、DNS、防火墙、断网）；提示中会建议检查网络后重试 |
| `未找到可用更新（仓库中暂无发布版本）` | 发布仓库尚无正式版本 |
| `未找到安装包（发布资产中缺少 Setup 安装程序）` | 该次发布未上传安装包资源 |
| `下载失败（HTTP …）` | 下载中断或地址失效，可重试 |
| `安装包尚未下载完成` | 在下载未完成时点了安装 |
| `打开安装包失败，请手动运行：…` | 系统没有关联的程序可打开安装包，按提示的路径手动双击 |

安装包会先存到程序缓存目录，启动时自动清理上一次遗留的安装包，不会长期占用磁盘。

### 4.1 安装包的摘要从哪来

下载完成后，程序会把安装包的 SHA-256 与两份来源对账：一份是随发布资产提供的摘要，另一份是仓库里独立维护的 `release-trust.json`（经 GitHub raw 读取）。两者一致才继续；不一致直接停止并提示「发布清单与发布资产摘要不一致」。

如果独立清单暂时读不到（比如刚发版还没来得及更新），程序仍按发布资产的摘要校验，但会在弹窗里提示「摘要未独立确认」；连资产摘要也没有时提示「仅按大小校验，请核对来源」。看到这两句时，建议去发布页核对后再安装。

### 5. 更新历史

- 弹窗下半部分是 `更新历史`，按版本倒序列出该版本的改动，可滚动查看。
- 这是一份随发版手工维护的说明，不是自动生成的提交日志；没有列出的小改动也可能包含在某版本中。
- 内容来自仓库根目录的 `CHANGELOG.md`：发版时只需在该文件开头追加一节（`## 版本号 · 日期` + 若干 `- 条目`），应用内会自动解析并按日期倒序展示。

### 6. 版本号怎么读

版本号形如 `主版本.次版本.修订号`，例如 `0.1.0`：

- 次版本与修订号增加通常表示功能与修复；
- 主版本变化可能包含界面与流程调整，升级前建议先看更新历史与相关篇目。

> **建议**：升级前导出一份备份（`设置 → 账号管理 → 导出数据库`），升级后打开几个常用页面确认数据正常。
